# Панель автора

**[Открыть админку](https://heskuchai.github.io/tier-of-everything/admin/)**

## Что можно делать

- Создавать и редактировать тирлисты через формы, без ручного JSON.
- Менять названия, описания, критерии, категории и цвет обложки.
- Добавлять предметы, выбирать уровень S-F и писать пояснения.
- Загружать картинки с компьютера или вставлять HTTPS-ссылку.
- Смотреть предпросмотр до публикации.
- Хранить черновик в браузере, скачивать его копию и переносить её на другое устройство.
- Отправлять каталог и загруженные изображения в GitHub одним коммитом.

## Первое подключение GitHub

Нажмите **Подключить GitHub**. В диалоге есть пошаговая инструкция.

1. Войдите в аккаунт **Heskuchai** и откройте [создание fine-grained personal access token](https://github.com/settings/personal-access-tokens/new).
2. Название, например: `Tier author panel`. Выберите ограниченный срок действия.
3. В **Repository access** укажите **Only select repositories** и только **tier-of-everything**.
4. В **Repository permissions** дайте **Contents: Read and write**. Metadata: Read-only добавляется GitHub автоматически. Права на другие репозитории, Workflows и Administration не нужны.
5. Создайте ключ, скопируйте и вставьте в поле панели. Не присылайте ключ в чат и не записывайте его в репозиторий.

Панель проверит аккаунт и загрузит актуальный каталог. Ключ передаётся напрямую в `api.github.com` по HTTPS и хранится только в памяти вкладки. Он не попадает в IndexedDB, localStorage, резервные копии или опубликованные файлы. После перезагрузки ключ нужно ввести повторно. Кнопка **Heskuchai · Выйти** удаляет ключ из памяти. Неиспользуемый ключ можно отозвать в настройках GitHub.

Это статическая админка: сам URL и код открыты. Доступ к записи защищает GitHub, а не скрытый адрес или пароль в JavaScript. Посетитель без вашего ключа может создать свой локальный черновик, но не может изменить ваш репозиторий или сайт. Редактор допускает публикацию только от Heskuchai. Не размещайте черновики с конфиденциальным содержимым на общем компьютере.

Настройки ключа описаны в [документации GitHub](https://docs.github.com/en/authentication/keeping-your-account-and-data-secure/managing-your-personal-access-tokens).

## Создать тирлист

1. Нажмите **+ Новый тирлист**.
2. Заполните название, описание и критерий оценивания.
3. Выберите категорию, цвет и значок. При желании добавьте обложку.
4. Нажмите **+ Добавить предмет**, укажите название, уровень S-F, пояснение и значок. Можно добавить картинку.
5. Откройте **Предпросмотр**.
6. Нажмите **Опубликовать**, коротко опишите изменения и подтвердите отправку.

Дата обновления и запись в журнале формируются автоматически по времени Киева. Идентификаторы создаются автоматически и остаются постоянными при переименовании.

## Картинки

- Файлы: JPG, PNG и WebP, до 10 МБ. Панель пересохраняет изображение в WebP, уменьшает длинную сторону до 1400 пикселей и принимает результат до 1 МБ. Оригинал и его метаданные не загружаются. Нужен современный браузер с поддержкой WebP и createImageBitmap.
- Файлы публикуются в `media/` репозитория под случайным именем. Они станут общедоступными вместе с сайтом. Старые неиспользуемые файлы автоматически не удаляются, чтобы не ломать ссылки из истории.
- Для URL нужна прямая HTTPS-ссылка на изображение. Страница сайта с фотографией вместо файла не подходит. Ссылка остаётся внешней: доступность картинки зависит от её владельца. Панель не копирует такие изображения в GitHub.
- Для PNG-экспорта внешний сервер должен разрешать CORS. Если он не разрешает, картинка в скачанном PNG заменяется значком, а сайт сообщает об этом. Загруженные в репозиторий изображения экспортируются с сайта без этого ограничения.
- Значок нужен как запасной вариант, если картинка недоступна.

## Черновики

Изменения сохраняются в IndexedDB браузера. Это не публикация и не серверная резервная копия. При очистке данных браузера черновик исчезнет. Кнопка **Копия черновика** скачивает JSON вместе с подготовленными изображениями, но без ключа. Через **Импорт копии** его можно открыть на другом устройстве. Максимальный размер импортируемой копии - 30 МБ.

Если изменился каталог в GitHub, панель остановит публикацию, сохранив черновик. Сначала скачайте его копию, затем нажмите **Загрузить из GitHub** и внесите нужные изменения в свежую версию. Панель не перезаписывает чужие коммиты принудительно.

## После нажатия «Опубликовать»

Панель подтверждает сохранение в GitHub и даёт ссылку на **Actions**. Сам сайт обновляется после успешного workflow **Build and publish**, а не сразу после коммита. Если сборка завершилась ошибкой, предыдущая опубликованная версия остаётся доступной. Журнал Actions покажет причину.

Вкладку с админкой можно закрыть после подтверждённой отправки в GitHub: дальнейшая сборка выполняется на GitHub. Если ошибка произошла до подтверждения, проверьте историю коммитов перед повтором и сохраните копию черновика.
